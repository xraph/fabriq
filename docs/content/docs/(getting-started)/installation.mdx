Fabriq is both a Go library you import (`github.com/xraph/fabriq`) and a single binary (`fabriq`) that runs the background worker plane and the operator commands. This page covers what you need installed, how to pull the module, and the order to bring a service up.

## Prerequisites

- Go 1.26 or newer. The module declares `go 1.26.0` in `go.mod`.
- PostgreSQL, the source of truth. The command store, the relational, time-series, vector and spatial ports, and projection bookkeeping all live here, so Postgres is the one store Fabriq can't run without.
  - The TimescaleDB extension for hypertable telemetry (the `TSQuerier` bulk-write path).
  - The pgvector extension for the embedding port (`VectorQuerier`, HNSW similarity search).
  - The PostGIS extension for the spatial port.
  - The migrations check `pg_available_extensions` and skip an extension the server doesn't have, so a plain Postgres still serves commands, relational reads, projections and subscriptions. Only the matching planes need the extensions. The `timescale/timescaledb-ha:pg16-all` image has all three.
- Redis, for live subscriptions and for running projections. The outbox relay publishes change channels to Redis Streams and the subscription hub tails them. Without Redis, commands and relational reads still work, but `Subscribe` and the graph and search projections don't.

Optional, enabled per data plane:

- FalkorDB backs the graph projection (`GraphQuerier`, openCypher). Without it, `Graph()` returns a not-configured port.
- Elasticsearch backs the search projection (`SearchQuerier`). Without it, `Search()` returns a not-configured port.

<Callout type="info">
Every optional store degrades to a typed `ErrStoreNotConfigured` rather than a nil panic. A minimal deployment is Postgres plus Redis; add FalkorDB and Elasticsearch only when you turn on the graph and search projections. See [Configuration](/docs/configuration) for the toggles.
</Callout>

## Getting the module

```bash
go get github.com/xraph/fabriq
```

To install the operator and worker binary:

```bash
go install github.com/xraph/fabriq/cmd/fabriq@latest
```

The root module requires `github.com/xraph/fabriq/core` at a tagged version, so `go get` resolves everything from the module proxy. The root `go.mod` replaces `core` with `./core` only for work inside this repository.

## First steps

Bring a service up in two distinct phases: apply migrations once as an operator step, then start serving. Don't fold schema migration into request-path startup.

<Steps>

<Step>
**Apply migrations.** Run grove's migrations against the database before anything serves. It takes an advisory lock, so it's safe to run from a one-shot Job even with several replicas waiting.

```bash
fabriq migrate up --dsn "postgres://user:pass@localhost:5432/fabriq?sslmode=disable"
```

The DSN can also come from `FABRIQ_POSTGRES_DSN`; `--dsn` overrides it. See [Migrations](/docs/migrations) for the full `up`/`down`/`status` workflow.
</Step>

<Step>
**Declare your entities and open the facade.** In library code, build a registry, register a `registry.EntitySpec` for each of your entities, then call `fabriq.Open`. The registry doesn't create tables for static entities, so each entity's table comes from your own migration, run after Fabriq's. Postgres is mandatory; Redis turns on subscriptions and projections.

```go
reg := registry.New()
if err := reg.Register(registry.EntitySpec{
	Name:      "note",
	Kind:      registry.KindAggregate,
	Model:     (*Note)(nil), // a grove model with id, tenant_id and version columns
	Subscribe: []registry.Scope{registry.ByID, registry.ByTenant},
}); err != nil {
	log.Fatal(err)
}

f, stores, err := fabriq.Open(ctx, reg, fabriq.Config{
	Postgres: fabriq.PostgresConfig{DSN: "postgres://user:pass@localhost:5432/fabriq?sslmode=disable"},
	Redis:    fabriq.RedisConfig{Addr: "localhost:6379"},
})
if err != nil {
	log.Fatalf("open fabriq: %v", err)
}
defer f.Close()

_ = stores // worker-plane wiring (relay, electors, projection consumers)
```

`Open` returns the `*fabriq.Fabriq` facade your application holds, plus a `*fabriq.Stores` handle the worker plane uses for the relay, leader election and projection consumers. The [Quickstart](/docs/quickstart) has the full program, including the `Note` model and its migration.
</Step>

</Steps>

`domain.RegisterAll` registers the example domain pack (site, asset, tag, page) that the `fabriq` binary uses. Don't build on it in your own service. Fabriq's migrations no longer create its tables (migration `0003` is a no-op now and the DDL lives in `domain.DemoDDL()`), so writes against those entities fail with `schema_mismatch` unless you apply that DDL yourself. Declare your own entities and tables instead.
