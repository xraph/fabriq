The **fabriq-admin console** is a web dashboard over a running fabriq instance. It talks
to the [adminapi](/docs/remote-protocol) HTTP surface (`forgeext/adminapi`) — the same
surface the [connection string](/docs/connection-string) and remote clients use — and
renders one interactive surface per subsystem. It is a library-first, runtime-pluggable
React app: mount `<FabriqAdmin>` into a host app, or run the bundled `cmd/admin-demo`.

![The fabriq admin console](/admin-console.png)

Every request is [tenant-scoped](/docs/tenancy): a tenant switcher sets `X-Tenant-ID`, and
all reads and writes route to that tenant. Each surface is capability-gated — it renders
only when the instance advertises the backing capability, and write controls appear only
when the matching write capability is present.

## Running it

The console needs a fabriq instance exposing the adminapi. The quickest path is the
bundled demo, which stands up the full stack (Postgres, Elasticsearch, FalkorDB, Redis,
a `file://` blob store) and seeds illustrative data:

```bash
# from the fabriq repo — serves the adminapi on :8080
go run ./cmd/admin-demo
```

Point the console at it (defaults to `http://localhost:8080/admin`):

```bash
# from the fabriq-admin repo
pnpm --filter @fabriq/host dev   # Vite dev server, opens the console
```

By default the demo runs **unauthenticated** — the console loads straight in. To require
credentials, enable [authentication](/docs/authentication) and, optionally, a
[dashboard login](/docs/authentication#dashboard-login).

## Running the container image

The console also ships as an image, `ghcr.io/xraph/fabriq-admin` (version `0.1.0`, also tagged `0.1`, for `linux/amd64` and `linux/arm64`). It serves the built console on port `8080` and can proxy the admin API of a [hosted server](/docs/deployment#hosted-server), so the browser only ever talks to one origin.

```yaml
services:
  fabriq:
    image: ghcr.io/xraph/fabriq:1.9.0
    environment:
      FABRIQ_POSTGRES_DSN: postgres://fabriq_app:...@pg:5432/fabriq?sslmode=require
      FABRIQ_REDIS_ADDR: redis:6379
      FABRIQ_ADMIN_API: "true"
      FABRIQ_ADMIN_KEY: ${FABRIQ_ADMIN_KEY}
      FABRIQ_DOMAIN_PACK: none

  fabriq-admin:
    image: ghcr.io/xraph/fabriq-admin:0.1.0
    ports: ["8080:8080"]
    read_only: true
    tmpfs: ["/tmp"]
    environment:
      FABRIQ_ADMIN_UPSTREAM: http://fabriq:8081
      FABRIQ_ADMIN_UPSTREAM_KEY: ${CONSOLE_KEY}
      FABRIQ_ADMIN_DEFAULT_TENANT: acme
```

`GET /healthz` returns 200 `ok`, which is what your orchestrator should probe. The container runs as uid 101 and only needs `/tmp` to be writable, so a read-only root filesystem works with an `emptyDir` or a tmpfs mounted there. If an environment value is invalid, the container exits 1 at start.

| Variable | Meaning |
| --- | --- |
| `FABRIQ_ADMIN_UPSTREAM` | The fabriq server's origin, for example `http://fabriq:8081`. The container proxies `/admin/` there, and server-sent events pass through. |
| `FABRIQ_ADMIN_UPSTREAM_KEY` | A key that can manage keys. The proxy adds it as `Authorization: Bearer` and overrides anything the browser sends. |
| `FABRIQ_ADMIN_BASE_PATH` | The external prefix a prefix-stripping proxy serves the console under. Defaults to `/`, and must start and end with `/`. |
| `FABRIQ_ADMIN_DEFAULT_TENANT` | The tenant preselected when the browser hasn't chosen one. |
| `FABRIQ_ADMIN_API_URL` | The admin API URL, for when you aren't proxying. |
| `FABRIQ_ADMIN_MAP_STYLE_URL` | An optional map style for the spatial surface. |

For the upstream key, issue a dedicated multi-tenant key with `canManageKeys` on, labelled something like `fabriq-admin-console`, so you can revoke it without touching anything else. The bootstrap `FABRIQ_ADMIN_KEY` works too. With a key injected, the console needs no login.

That also means the container is a way into your server for anyone who can reach it. Put it behind your own authenticated proxy and never route it to the public internet.

## Mounting into a host app

The console is a library. Import `<FabriqAdmin>` from `@fabriq/admin-sdk` and give it a
client:

```tsx
import { FabriqAdmin, connect } from "@fabriq/admin-sdk"

// Build a client from a connection string (carries endpoint + tenant + credential):
const client = connect("fabriq://<key>@fabriq.internal/acme-corp")

export function Console() {
  return <FabriqAdmin client={client} plugins={[/* built-in + remote */]} />
}
```

See [Connection string](/docs/connection-string) for how a client is built from a
`fabriq://` DSN, and [Authentication](/docs/authentication) for API keys and login.
